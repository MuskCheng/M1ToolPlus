本次发布沿用 v1.8.1 的读写卡业务逻辑，改动集中在界面细节与设备状态反馈。

### 界面

- 状态栏改为自适应排布：最左「空闲 / 运行中」与最右「检查更新」固定不被挤掉，中间各项按剩余空间均分，窗口变窄也不会吞掉任何一项
- 复制卡页的「请放原卡 / 请放新卡」两条提示改为 14px 粗体 + 高对比强调色，不再与旁边一排蓝色按钮同质
- 「请放新卡」移到右箭头下方，改成一行一字竖排，整块在两个分组之间垂直居中

### 设备状态

- 启动后静默检查一次更新：远端有更新才把状态栏右侧的「检查更新」换成「有新版本」，无更新或网络异常完全无感
- 底部「设备串口：」前缀常显，只在后面跟具体串口号；未检测到设备时后面留空，不再整条消失
- 拔出读卡器后串口号**一秒内**清空（此前要等十几秒的重新扫描），终端不再刷 `Invalid serial port` 之类的试探报错
- 修掉这一路径上的三个问题：静默扫描没有先删 `libnfc.conf`（会在失效串口上阻塞近 40 秒）、串口显示要等完整扫描结束、`timer1` 缺少互斥导致重入死循环

### 更新包校验

下载 `M1ToolPlus-v1.8.2.zip` 后可与 `SHA256SUMS.txt` 核对：

```
certutil -hashfile M1ToolPlus-v1.8.2.zip SHA256
```

程序内的「检查更新」同样会比对 GitHub 附件的 SHA256，校验不通过不会解压覆盖现有文件。

### 依赖

`nfc-bin\` 内的 libnfc、mfoc、mfcuk 等工具不入版本库，由发版流水线从上游 `xcicode/MifareOneTool v1.7.0` 的 Release 资产自动还原后打进包里，解压即用。

### 已知限制

- 需要 .NET Framework 4.0 运行时（Windows 10 / 11 已内置）
- ACR122 开关会真实改写 `nfc-bin\libnfc.dll`，因此不提供单文件打包形式
