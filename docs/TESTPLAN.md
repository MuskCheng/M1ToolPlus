# 真机回归测试清单（M1ToolPlus）

> 用途：本环境无 NFC 硬件，#26 修复、界面改名、语言切换等改动只能编译 + 启动验证。
> 请按本文档在有 PN532 / ACR122U 的机器上执行，结果回填到 docs/ROADMAP.md「三、待办 B 区」或提 issue。
> 最后更新：2026-10-21。

## 0. 测试前准备

| 项 | 说明 |
|---|---|
| 读卡器 | PN532（推荐）/ ACR122U（需在界面里手动开启 ACR122U 支持） |
| 驱动 | CH340/CH341 串口驱动请自行从沁恒官网安装（我们不随包分发驱动） |
| 测试卡 | ① 空白/普通卡（默认 Key FFFFFFFFFFFF）② SAK=08 半加密卡 ③ 已知密钥卡 ④ UID/CUID 类卡 |
| 被测程序 | `M1ToolPlus\bin\Release\M1ToolPlus.exe`（已含 `nfc-bin\` 运行依赖） |
| 注意 | 发布包**不含 `mff08.exe`**（来源不明，合规剔除，见 docs/DEPENDENCIES.md）；MFF08 对话框应提示并自动关闭 |
| 日志 | 界面「保存日志」按钮 → `m1t.log`；问题描述请附关键日志片段 |

## 1. P0 冒烟（改名后首跑）

- [ ] 启动后主窗口标题为 `M1ToolPlus`
- [ ] 首次运行会新建用户配置（改名 = 新身份），请重新设置语言、设备、`NewScan` 等偏好
- [ ] 界面文案无空白/乱码（中文/英语/俄语，下拉索引 0=简体中文 1=Русский 2=English）
- [ ] 点「MFF08」按钮：应弹出「无法找到 MFF08 程序文件，操作终止」并**自动关闭对话框**（不应崩溃）
- [ ] **高 DPI 1:1**：在 125%/150% 缩放下首次启动，窗口应为 **900×839 物理像素**左右（不再被系统放大到 1125×1020），
      文字边缘清晰不发虚；窗口应完整落在桌面工作区内、四边都能拖动缩放；
      需要核对数值时运行 `M1ToolPlus.exe --ui-info`，结果在 `%TEMP%\m1tool-ui-info.txt`（含 `DeviceDpi`、`ClientSize`、关键控件 `Bounds`）
- [ ] 切换系统主题（深/浅）后重启，界面配色与标题栏均为对应深色/浅色（不是白标题栏）

## 2. #26 设备扫描回归（本次核心修复）

- [ ] 启动后自动恢复上次使用的设备（有「已恢复上次使用的设备」提示）
- [ ] PN532：检测连接耗时（改前 Win10 常 100s+）
- [ ] ACR122U：开启 ACR122U 支持后，检测/读/写延迟（#26 报告称 ACR122U 所有操作约 100s，属另一根因，需分开观察）
- [ ] 设备名识别变体：`pn532_uart` / `pn532_uart:COMx` / `acr122_pcsc` 等
- [ ] 热插拔读卡器后重新扫描

## 2b. 2026-10-16 修复项专项验证（对照 docs/FIXPLAN.md）

- [ ] **设备扫描超时**：拔掉读卡器后点「检测」，应在 60 秒内自动终止并提示，不再永久停在"运行中"（修复前 #39/#26）
- [ ] **ACR122U 开关**：点「启用 ACR122U 支持」→ 终端出现「已切换为 ACR122U 兼容（慢速）模式」；再点一次 → 「已切回默认驱动」；确认 `nfc-bin\libnfc.dll.acr122u.bak` 生成且可反复切换（修复前开关完全无效，#9/#31）
- [ ] **ACR122U 连接**：切换到兼容模式后用 ACR122U 读写一张卡，确认能连上；切回默认模式再试一次对比
- [ ] **终端区可见/有输出**：点「检测连接」后终端区应立即出现「开始执行检测设备……（扫描可能需要数十秒，请稍候）」，
      随后输出 `nfc-scan-device` 的完整原始日志与识别到的设备列表；不能出现"日志框空白"或文字被页签遮住
      （修复前 RichTextBox 被 Tab 控件盖住前 300+ 像素，且设备扫描的 stdout 未回显）
- [ ] **终端输出编码**：执行任意操作，确认 libnfc 的中文提示（如"探测到设备"、"NFCID1"、"未发现卡"等）
      **不再乱码**（nfc-bin 工具按 GBK/936 输出，已固定用 936 解码；修复前按 UTF-8 解码会显示 `ʹ��` 之类，#28/#34/#35）
- [ ] **窗口未激活时点按钮不崩溃**：用键盘/自动化方式在窗口未激活时触发「检测连接」，不应弹出
      「.NET Framework 未处理异常」（修复前 `Form1.ActiveForm` 为 null 会抛 NullReferenceException）
- [ ] **mfoc 字典模式**：用密钥字典（.dic）跑一次 MFOC，输出显示在界面终端区而非另开 cmd 窗口，退出码判断正确（#35/#42）
- [ ] **缺文件保护**：临时把 `nfc-bin` 目录改名后点任意工具按钮，应提示错误而不是崩溃退出

## 2c. 2026-10-21 终端字体/字号专项

- [ ] 终端中文默认字体为**微软雅黑**（Microsoft YaHei UI），中英混排基线一致、无方块字
- [ ] 默认字号 **10.0 磅**（比界面 9pt 大一号）；旧配置升级后设置页也应显示 10.0
      （`TerminalFontVersion` 一次性迁移，旧值从未生效过，升级后统一提升）
- [ ] 设置页「终端文字大小」与实际一致：改成 12.0 后终端立刻变大，重启后仍是 12.0
- [ ] 终端上 **Ctrl+滚轮**（鼠标悬停即可，无需先点选）：上滚 +1 磅、下滚 -1 磅，
      设置页数字同步变化；到 7 / 36 边界后不再变化
- [ ] 滚轮调过字号后重启，字号保持（`user.config` 的 `MainCLIFontSize` = 调后的值）
- [ ] 切换系统深/浅色主题（或重启）后，终端仍是雅黑 + 用户字号，没有退回 Consolas
- [ ] 7 / 36 磅两端字号下日志不裁切、不乱行
- [ ] 自检：`M1ToolPlus.exe --ui-info` → `TerminalFontSize` 与设置页一致、
      `TerminalFontFamily=Microsoft YaHei UI`、`TerminalZoom=1`（必须恒为 1，滚轮后也不能变）

## 3. 功能冒烟（核心路径）

## 4. 语言切换回归

- [ ] 设置页语言下拉框选 Русский / English，程序自动重启后**主界面立即变为对应语言**
      （页签标题、按钮、状态栏、对话框都要看）
- [ ] **下拉框回显**：启动后设置页语言下拉框应显示当前语言——
      中文界面 `简体中文`、俄语 `Русский`、英语 `English`（不能空白）
- [ ] 三语切换后主界面、错误提示、各对话框均有对应文案（重点：新增的「已恢复上次使用的设备」zh/ru/en）
- [ ] 英语/俄语文案较长，切换后按钮/标签不截断（窗口会按文案自动加宽，见 `UiTheme.ApplyAdaptiveLayout`）；
      俄语窗口高度应与中文一致（125% DPI 下均为 839 物理像素），复制模式卡片不应被拉宽或箭头错位

- [ ] 自检：`M1ToolPlus.exe --ui-info` → `%TEMP%\m1tool-ui-info.txt` 里
      `SettingLanguage`、`CurrentUICulture`、`TabPage1Text` 三行语言一致，
      `LanguageCombo` 与当前语言对应
